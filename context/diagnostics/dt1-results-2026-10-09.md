# DT-1 results (2026-10-09) — the daily-trend strategy does not generalize; it inverts

**Pre-registered per `dt1-pre-registration-2026-10-09.md`, run explicitly underpowered by user decision (option 3) after Stage B's power simulation showed only 3–4% power to detect the required Sharpe=0.54 at this precision.** The result below is not the ambiguous, wide-interval outcome that framing might suggest — it is a decisive, confidently **negative** finding, and §2 explains why that is still consistent with a genuinely low-power design.

Config: `r4-daily-trend@5641c13b3b6886aa40fab351382895a4bc2a47d9d223010031fc90536e876e11` (verified against the pre-registered hash at run time — the run refuses to proceed on a mismatch). Universe: `dt1-v3`, 159 external sleeves (every `dt1-v3` member except BTC/ETH, per A6), 0 skipped. Data: `historical_bars` (Binance spot, 1d+4h), fully backfilled for all 159 assets before this run (see §6 — 4h bars did not exist for the external universe until this unit; see Appendix for the ingestion incident).

## 1. Headline result

| Statistic | Value |
|---|---|
| **E1 — annualized Sharpe (equal-weight external-sleeve portfolio curve), 90% bootstrap CI** | **−0.737, [−1.273, −0.165]** |
| **E2 — pooled expectancy (n=3,301 trades), all three estimators** | **−0.179R, significant, negative** (ICC [−0.323,−0.035], Newey-West [−0.338,−0.019], block bootstrap [−0.255,−0.103]) |
| DSR N=1 | sharpePerPeriod = −0.0386, DSR = 0.014 |
| DSR N=14 | ≈ 0.000 (see §5 — certain regardless of the omitted skew/kurtosis correction, since a negative observed Sharpe cannot clear a positive SR0 benchmark) |
| CPCV (45 time-block folds) | median Sharpe −0.706, range [−2.242, +0.256] |
| BTC/ETH continuity re-run | BTC Sharpe +0.305 (154 trades), ETH Sharpe +0.135 (168 trades) |

**The entire 90% CI on E1 sits below zero, and its upper bound (−0.165) is nowhere near the +0.54 economic hurdle.** E2's three independent dependence-corrected estimators all agree: significant, negative. This is not an inconclusive result — it is a clean, decisive one, in the opposite direction from what would be needed to advance the strategy.

## 2. Why this is resolvable despite Stage B's low-power finding

Stage B's power simulation measured the probability of **confirming a true Sharpe of exactly +0.54** at this sample size: 3–4%. That is a real, correctly-computed limitation — and it still holds. It does **not** mean every possible true effect is unresolvable at this precision; it means a **marginal positive effect specifically at +0.54** is hard to distinguish from zero.

The real data did not land near +0.54. They landed at **−0.737**, roughly 1.3 Sharpe units away from the hurdle. A large deviation from a threshold is easier to resolve than a marginal one, even at the same sample size — and the realized evidence confirms this is not a coincidence of methodology: **the observed CI width (−0.165 − (−1.273) = 1.108) matches the Lo (2002) asymptotic prediction from the Stage B report (1.123) almost exactly.** The simulation correctly predicted how wide this interval would be; what nobody could predict in advance was where the point estimate would land. It landed decisively on the negative side, far enough out that even a ~1.1-wide interval excludes +0.54 with no ambiguity.

## 3. The "Supported" verdict (§6.8, A10)

All three conditions were required for "Supported"; **condition 1 fails decisively on its own** — E1's CI upper bound (−0.165) is nowhere close to the required 0.54 — so conditions 2 (MaxDD veto) and 3 (robustness) are moot and were not computed (see §6). Per A10, this was already true structurally before the run (an underpowered design can never be labeled "Supported"); it is now also true empirically and without ambiguity. **Verdict: Not Supported — and the point estimate itself is negative, not merely unresolved.**

## 4. Generalization does not merely fail — it inverts

| | Sharpe |
|---|---|
| BTC (continuity re-run, same config) | **+0.305** |
| ETH (continuity re-run, same config) | **+0.135** |
| External universe, 159 assets, primary (E1) | **−0.737** |

R4's original discovery assets still show the same weak positive signal reported in the original R4 run. The external universe does not replicate that signal at a smaller magnitude — it **inverts** to a confidently negative one. This is the direct answer to DT-1's question: the daily-trend baseline's apparent edge on BTC/ETH does not generalize to a broader liquid-asset universe.

## 6. What was deferred, and why — nothing silently omitted

- **MaxDD veto (condition 2 of §6.8).** Not computed. Moot: condition 1 already fails decisively, so the full three-condition verdict cannot change regardless of the drawdown figure.
- **Funding overlay (§5.6).** Not computed, and **not applicable** — R4's daily-trend strategy is long/flat only (zero `OPEN_SHORT` ever proposed), pays zero funding by design, exactly as R4 itself was pre-registered. There is nothing for a short-funding overlay to apply to.
- **DSR N=14's exact value** (vs. the ≈0.000 structural bound reported above) — the precise skew/kurtosis-adjusted figure needs the full daily return series, which a transient infrastructure incident (below) prevented from being saved to the committed results artifact in time. The direction and near-zero magnitude are certain regardless; the exact figure is a cheap, low-priority follow-up.
- **Per-asset display filtering (10-trade floor, §6.3)** — not applied in this write-up; `perAssetTradeCounts` in the committed JSON has the raw counts for anyone who wants to apply it.

## 7. Two secondary observations, reported for completeness

- **Drawdown breaker never tripped, in any of the 159 sleeves (0 rejections total).** This contrasts with R4's own BTC-only historical run, where the breaker tripped in 2020 and stayed tripped for 6.6 years. The difference is sample size per sleeve: most external sleeves accumulate only a handful to a few dozen trades each (median well under 20), far too few to compound a 50%+ drawdown the way a single asset held continuously for 9 years could. This is a property of the diffuse per-asset design, not evidence the strategy is safer on the broader universe.
- **15 assets still held an open position at the data cutoff** (ADA, BNB, BNX, DOGE, ENA, LINK, NEAR, PEPE, PUMP, PYTH, SOL, SUI, UNI, XPL, XRP). This is **not** delisting — these are large, actively-trading assets; the backtest simply reached "now" mid-position. No `delisted_close` event occurred in this run.

## Appendix — a real infrastructure gap found and fixed before this run

Phase 3 (universe data infrastructure, 2026-10-09 earlier) only bulk-ingested **daily** bars for the 159 external candidates — never 4h, which R4's ATR calculation requires. This was found immediately when the first run attempt returned zero 4h bars for every external asset outside BTC/ETH/SUI/AVAX. Fixed by backfilling 4h bars for all 164 (underlying, Binance-symbol) pairs via the existing `ingest-historical-bars` function; two retry passes were needed after sustained PostgREST statement timeouts (table contention under repeated large upserts) — all 164 pairs eventually ingested cleanly with zero permanent failures. `run-dt1.ts` itself was also hardened with a 3-attempt retry (exponential backoff) around each per-asset fetch, since a single transient timeout had crashed an earlier full run 30 assets in.
